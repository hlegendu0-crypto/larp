# LarpBattle

Платформа live 1v1 видео-баттлов: игроки показывают в камеру свои вещи, AI распознаёт предметы и оценивает их рыночную стоимость. Побеждает больший **Flex Score**. Победы двигают ELO-рейтинг и ранги.

**Текущий статус: Этап 4 — прод-обвязка (аккаунты, серверный ELO, античит-база, модерация). Все этапы ТЗ реализованы.**

Длительность раунда — **20 секунд** (параметр: `src/lib/config.js` на клиенте, `ROUND_MS` в `server/index.js`).

## Что реализовано (этап 1)

- **Лендинг** — хиро, live-счётчик онлайна, «Как это работает», топ-5 лидерборда, футер (правила / ToS / Privacy / 18+)
- **Авторизация** — заглушка: вход по нику + подтверждение 18+ (email/OAuth — этап 4)
- **Camera Check** — реальная камера через `getUserMedia`, индикаторы освещения/фрейминга, подсказки
- **Лобби** — «Быстрый матч» (симуляция очереди, ELO ±150 с расширением) и «Вызов друга» (инвайт-ссылка, демо-вход)
- **Экран баттла** — заставка VS → отсчёт 3-2-1 → раунд 60 сек: своя камера реальная (PiP, переключаемо), соперник — симуляция, live-лента распознаваний, анимированные Flex Score c «перетягиванием» лидерства, челлендж-оверлеи, сдаться/репорт/выход
- **Результаты** — «Идёт подсчёт…», победитель, разбивка по айтемам с причинами незачёта, дельта ELO, реванш/новый матч/поделиться
- **Лидерборд** — топ по ELO с закреплённой строкой своей позиции
- **Профиль** — ELO, ранг, винрейт, история матчей, самый дорогой айтем
- **Настройки** — ник, устройства, удаление аккаунта; страницы правил, ToS, Privacy

Прогресс игрока хранится в `localStorage`.

## Что реализовано (этап 2) — режим «Оцени мой флекс»

Реальный AI-пайплайн оценки по ТЗ §7.1–7.3, соло-раунд без соперника (вход из лобби):

- **Захват кадров** (`src/lib/capture.js`, `phash.js`) — тик каждые 500 мс, перцептивный
  хэш dHash 256 бит; на анализ уходит кадр только когда картинка стабильна ~1 с **и**
  сцена отличается от последней проанализированной. Лимит 15 кадров на раунд +
  минимальный интервал 2,5 с — контроль стоимости (ТЗ §11).
- **Vision-анализ** (`src/lib/vision.js`) — Claude API из браузера (официальный SDK),
  строгий JSON через structured outputs: `items[{name, category, est_price_usd,
  confidence, is_screen_or_photo}]`, `nsfw`. Промпт версионируется (`flex-appraiser-v1`).
- **Подсчёт** — дедуп по нормализованному названию, порог `confidence ≥ 0.5`,
  `is_screen_or_photo` → страйк (3 страйка = дисквалификация), `nsfw` → мгновенная
  остановка раунда.
- **Настройки AI** — API-ключ (хранится в localStorage браузера) и выбор модели:
  Opus 4.8 (по умолчанию, максимум качества) / Sonnet 5 / Haiku 4.5 (укладывается
  в NFR ≤ $0.10 за раунд).

## Что реализовано (этап 3) — live 1v1

- **Сигналинг-сервер** (`server/index.js`, Node.js + ws): очередь матчмейкинга с подбором
  по ELO ±150 (окно расширяется на +100 каждые 10 с ожидания), приватные комнаты по
  инвайт-коду, ретрансляция WebRTC-сигналов, серверный таймер раунда и вердикт,
  техническая победа при сдаче/дисконнекте (ТЗ §6.5).
- **WebRTC** (`src/lib/rtc.js`) — прямое P2P-видео между игроками, свой сигналинг,
  perfect negotiation (роли polite/impolite выдаёт сервер).
- **Синхронизация счёта** — каждый игрок гоняет AI-пайплайн этапа 2 локально по своей
  камере; распознанные айтемы уходят на сервер (он ведёт авторитетный счёт) и
  ретранслируются сопернику в live-ленту.
- **Инвайт-ссылки** — `/#/join/CODE`: друг открывает ссылку и сразу попадает в бой
  (приватный матч, без рейтинга).
- **Фолбэк**: если сервер недоступен, лобби честно предупреждает и играет демо-баттл
  этапа 1 с симуляцией.

## Что реализовано (этап 4) — прод-обвязка

- **Аккаунты** (ТЗ §6.2): регистрация/вход email+пароль (scrypt-хэши, подписанные токены).
  Гостевой режим по нику остаётся для демо и соло; рейтинговые live-матчи — только с аккаунтом.
- **ELO/ранги/лидерборд на бэке** (§8): дельту считает сервер по авторитетному счёту
  (K=32, техническая — K=16), профиль и глобальный топ хранятся в БД,
  `/api/leaderboard` и `/api/me`.
- **Античит-база pHash** (§7.4): засчитанные айтемы (нормализованное имя + pHash кадра)
  пишутся в базу; повторный показ того же предмета в новых матчах в течение 7 дней
  даёт 0 очков (совпадение по имени или хэмминг-дистанции хэша).
- **Модерация и репорты** (§4, §7.4): кнопка «Репорт» пишет жалобу в очередь;
  админ-панель `/#/admin` (ключ — env `ADMIN_KEY`, по умолчанию `admin-dev-key`):
  разбор жалоб, баны/разбаны. Бан блокирует логин и очередь.
- **NSFW-автостоп** (§7.5): флаг vision-модели завершает бой техническим поражением
  нарушителя и автоматически банит его до разбора модерацией (+системная жалоба).
- **Дневной лимит баттлов** (§11): env `DAILY_BATTLE_LIMIT` (по умолчанию 30) —
  защита от выжигания бюджета.
- **БД** — SQLite через встроенный `node:sqlite` (файл `server/larpbattle.db`);
  схема переносится на PostgreSQL без изменений при масштабировании.

## Запуск

```bash
npm install
cp .env.example .env.local   # подставьте свой ключ Anthropic (или введите его в настройках приложения)
npm run server               # бэкенд на :8787 (API + сигналинг; нужен для аккаунтов и live 1v1)
npm run dev                  # http://localhost:5173 (отдельный терминал)
npm run build                # прод-сборка в dist/
```

Параметры сервера (env): `PORT`, `DB_PATH`, `ADMIN_KEY`, `DAILY_BATTLE_LIMIT`,
`ROUND_MS`, `VS_LEAD_MS`, `FINALIZE_MS`.

Адрес сигналинг-сервера настраивается через `VITE_SIGNALING_URL`
(по умолчанию `ws://<hostname>:8787`).

⚠️ `VITE_ANTHROPIC_API_KEY` из `.env.local` запекается в JS-бандл при сборке — это
удобно для локальной разработки, но такую сборку нельзя выкладывать публично.
Для деплоя оставьте переменную пустой: игроки вводят собственный ключ в настройках.
На этапе 4 вызовы AI переезжают на бэкенд.

## Стек

Клиент: React 18 + Vite + Tailwind CSS 4, React Router (hash-роутинг),
`@anthropic-ai/sdk` (vision, structured outputs), WebRTC.
Сервер: Node.js + `ws` + `node:sqlite` (API, сигналинг, матчмейкинг, счёт, античит, модерация).
